## IV. DISCUSSION

### 4.1 Interpretation of Algorithm Performance

The 1D CNN was the strongest individual classifier in the November 16 comparison. Its **91.2% macro accuracy** and **91.0% macro F1-score** indicate that its lead held when each stroke class counted equally. The LSTM trailed by one percentage point on both metrics and achieved the best serve F1-score. Its bidirectional recurrence preserves information from both sides of the hit window, while the CNN can evaluate local movement patterns across the window in parallel. The Random Forest offers NumPy-only inference and uses interpretable summary features such as joint angles and shuttle displacement. Summarizing the window reduces detail about the order of movements, which may help explain its weaker performance on drops. The CNN also had the smallest checkpoint and lowest median stroke-stage time in the CPU benchmark, supporting its selection as the default individual model. The close CNN–LSTM margin is descriptive because the same test split was consulted across development rounds. [Results](IMRAD_RESULTS.md#31-comparative-algorithm-performance), [CPU benchmark](results/stroke_latency.md), [default configuration](../backend/configs/pipeline.yaml)

Drop–smash confusion persisted across all three models. A plausible explanation is that both can share similar overhead preparation before contact, so differences in the later motion or resulting shuttle path matter. The CNN still classified 16.7% of drops as smashes, making drop labels a useful priority for review. [Confusion analysis](IMRAD_RESULTS.md#32-confusion-matrix-and-per-class-performance)

### 4.2 Interpretation of the Ablation Experiment

Normalized joint coordinates encode body configuration and movement through preparation, contact, and follow-through. The pose-only CNN reached **77.5% macro accuracy**, showing that joint motion carries useful stroke information. Adding shuttle position, visibility, and frame-to-frame displacement raised macro accuracy to **91.2%**, a gain of **13.7 percentage points**. Clear and drop showed the largest class-level F1 gains. A window around a hit lets the model associate a player's motion with the shuttle's movement before and after that moment. The experiment measures the benefit of adding shuttle features to pose. It leaves shuttle-only performance and the independent effect of frame order unresolved. [Ablation results](IMRAD_RESULTS.md#33-ablation-study-pose-only-vs-combined-features), [feature implementation](../backend/shuttlesense/strokes/features.py)

### 4.3 Computational and Implementation Considerations

For inference on one stroke window, let `T` be the number of frames, `F` the features per frame, `H` the LSTM hidden width, `R` the number of trees, and `D` their maximum depth. Class count, LSTM layer count, and direction count are fixed. The bounds below exclude detection, video decoding, and encoding. [Neural models](../backend/shuttlesense/strokes/model.py), [forest implementation](../backend/shuttlesense/strokes/rf.py)

| Classifier | Time per window | Working memory per window |
| --- | --- | --- |
| 1D CNN | `O(Σ Tₗ Kₗ Cₗ₋₁ Cₗ)` for convolution layers with output length `Tₗ`, kernel width `Kₗ`, and input/output channels `Cₗ₋₁`, `Cₗ` | `O(maxₗ Tₗ Cₗ)` across input and intermediate feature maps |
| Bidirectional LSTM | `O(T(FH + H²))` for input projection and recurrent processing | `O(T(F + H))` for input and the sequence used by temporal pooling |
| Random Forest | `O(TF + RD)` for summaries and worst-case tree traversal | `O(TF)` for the input and summary intermediates, plus resident tree arrays proportional to the stored node count for fixed class count |

The CPU handles work such as video decoding, input preparation, overlay drawing, and NumPy forest inference. Supported TrackNetV3 and neural classifier operations can run on the GPU via CUDA, while player detection and pose use the configured ONNX Runtime providers. Data transfers and synchronization still contribute to wall time. The renderer reads, annotates, and writes frames incrementally. At fixed settings, it performs one pass over the frames, with memory for frame buffers plus the saved analysis record. The sampled NVENC export took about as long as CPU `libx264`, and two-frame prefetch did not reduce median Watch analysis-to-save time. These trials support retaining the current defaults for the measured workload. [Integration report](results/watch_phase7_validation_report.md), [render implementation](../backend/shuttlesense/render/overlays.py), [export benchmark](results/watch_phase6_export_benchmark.md)

### 4.4 Practical Implications and AI Coach Integration

Recorded analysis lets players and coaches replay suspected hits, compare strokes across rallies, and use the court map and heatmap to review positioning. The heatmap reflects time at detected court positions and should be interpreted alongside the clip, especially when tracking has gaps. Go live offers feedback during a session, with saved replay for closer review. AI Coach uses retrieval-augmented generation to combine saved observations with badminton guidance. Players can use the summary to identify a focus for practice, open timestamped evidence in the detailed analysis, or ask follow-up questions. Coaches can use the cited moments to check whether a suggestion fits the player's movement and drill. [System outputs](IMRAD_RESULTS.md#34-system-implementation-and-demonstration-results), [AI Coach design](AI_COACH.md)

### 4.5 Limitations of the Study

The stroke comparison used broadcast singles, six classes, and pre-extracted features. Its results may shift on phone footage, in doubles, or on unfamiliar camera views. In the app, blur and occlusion can cause missed shuttle detections or uncertain player identity. Incorrect corner taps and changes in camera position can distort court projections. Hit detection errors also change the windows classified, so the stroke benchmark cannot establish end-to-end accuracy. The live model smoke test used a short generated clip and one server GPU. Capture rate, network delay, event look-ahead, and hardware can affect live responsiveness. Finally, AI Coach inherits any errors in its observations. Reference validation checks that cited evidence exists, while review of real practice clips is still needed to assess whether the advice is technically sound.
